# 1:1 로컬 메이트 — 실제 계정 2개로 전체 흐름 점검표

> 서버 규칙(98건)과 화면 흐름(가짜 서버)은 제가 확인했어요. 아래는 **실제 Supabase와 실제 로그인**으로 직접 확인하는 순서예요.
> 계정은 **A(여행자)** 와 **B(현지인)** 두 개가 필요해요. 하나는 일반 창, 하나는 시크릿 창(Ctrl+Shift+N)에서 쓰면 편해요.

## 0. 준비 (한 번만)
- [ ] Supabase SQL Editor 에서 003 · 004 · 005 · 006 · 007 SQL 이 모두 실행되어 있다(각 파일은 여러 번 실행해도 안전).
- [ ] 사이트를 Ctrl+F5 로 새로고침한다.

## 1. B(현지인) 계정 만들기
1. [ ] B 로 회원가입·로그인 → **MY → 내 현지인 프로필**
2. [ ] 도시(서울), 소개, 관심사, 언어를 채우고 **프로필 공개**를 켜고 **프로필 저장** → "저장했어요"
3. [ ] 저장 후 나타난 **만날 수 있는 날짜·시간**에서 **내일 이후 날짜**와 시간을 추가 → 목록에 보임
4. [ ] SQL Editor 에서 신원 확인(이메일만 B 의 것으로):
   ```sql
   update public.host_profiles set identity_status = 'verified', verified_at = now()
    where user_id = (select id from auth.users where email = 'B의_이메일');
   ```

## 2. A(여행자): 추천 → 요청
1. [ ] A 로 로그인 → 홈 **나와 취향이 맞는 로컬 메이트 찾기**
2. [ ] 관심사(B 와 겹치는 것), 도시 서울, 날짜(3번에서 넣은 날짜 포함)로 **추천 받기** → B 카드가 나온다(점수·이유·일정 표시)
3. [ ] 카드의 **프로필 상세 보기** → 자기소개·가능 일정이 보인다. 사진을 누르면 크게 보인다
4. [ ] **매칭 요청** → 일정 선택, 활동·장소·메시지 입력 → **요청 보내기** → "요청을 보냈어요"
5. [ ] 같은 날짜로 한 번 더 보내면 "이미 요청했어요" 가 뜬다(중복 방지)
6. [ ] **MY → 내 매칭 요청 → 보낸 요청**에 "응답 대기"로 보이고 **요청 취소** 버튼이 있다

## 3. B: 요청 처리 → 채팅
1. [ ] B 의 **받은 요청**에 A 의 요청이 보이고 **수락 / 거절** 버튼이 있다
2. [ ] **수락** → 상태가 "수락"으로 바뀌고 **메시지** 버튼이 생긴다
3. [ ] **메시지**(또는 MY → 메시지) → A 가 요청 때 쓴 문장이 첫 메시지로 보인다
4. [ ] 답장을 보낸다(Enter 로 전송)
5. [ ] A 화면(새로고침 없이)에 **몇 초 안에** 새 메시지가 나타난다(실시간. 안 되면 15초 안에 나타나야 한다)
6. [ ] A 가 답장하면 B 화면에 나타나고, B 가 읽으면 A 의 메시지에 **읽음** 표시가 붙는다
7. [ ] 메시지 목록(MY → 메시지)에 마지막 메시지와 **안 읽은 수**가 보인다

## 4. 만남 완료 → 후기
1. [ ] 만남 날짜가 아직 안 지났으면 **만남 완료** 버튼이 없다(정상). 시험하려면 SQL Editor 에서:
   ```sql
   update public.match_requests set meet_date = current_date - 1 where status = 'accepted';
   ```
   (시험용 요청 하나뿐일 때만 실행)
2. [ ] A 의 **보낸 요청**에서 **만남 완료** → 상태 "만남 완료", **후기 쓰기** 버튼이 생긴다
3. [ ] **후기 쓰기**: 별점을 다 안 매기고 저장 → 안내 문구, 10자 미만 → 안내 문구
4. [ ] 4개 항목 별점 + 10자 이상 후기 → 저장 → "후기를 올렸어요". 다시 열면 "내가 쓴 후기"로 보인다(중복 작성 불가)
5. [ ] B 의 프로필 상세(A 계정으로 열기)에 후기와 평균 별점·개수가 보인다
6. [ ] B 도 **후기 쓰기**로 A 에 대한 후기를 남길 수 있다

## 5. 차단 · 신고
1. [ ] 채팅 화면의 **차단** → 입력 칸이 닫히고 "차단한 사용자예요" 안내, **차단 해제**로 되돌릴 수 있다
2. [ ] 상대 메시지의 **신고**, 사용자 **신고**가 "신고했어요"로 처리된다(내 메시지·내 후기는 신고 버튼이 없거나 거절된다)

## 6. 막혀야 정상인 것
- [ ] 로그인하지 않으면 추천·요청·메시지가 로그인 안내로 바뀐다
- [ ] A 가 남의(제3자) 대화 주소(`#/messages/아무_id`)로 들어가면 "대화를 찾을 수 없어요"
- [ ] 예시 호스트(@demo.roamly.invalid)에게 보낸 요청은 응답이 오지 않는다(실제 사람이 아니라서)
