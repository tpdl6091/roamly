# Roamly 1:1 현지인 매칭 서비스 개발 요청

## 1. 프로젝트 개요

현재 개발 중인 여행 플랫폼 Roamly에 '취향 기반 1:1 현지인 매칭 서비스'를 구현해 줘.

Roamly는 여행자가 유명 관광지뿐 아니라 현지인의 일상, 숨겨진 장소, 로컬 문화와 사람을 발견할 수 있도록 돕는 서비스야.

이번 작업의 핵심은 사용자가 자신의 관심사와 여행 스타일을 선택하면, 해당 조건에 가장 잘 맞는 현지인 5명을 추천하고, 마음에 드는 사람에게 매칭을 요청할 수 있도록 만드는 것이야.

## 2. 개발 시 반드시 지킬 사항

- 기존 프로젝트의 폴더 구조, 프레임워크, 컴포넌트, 디자인 시스템을 먼저 확인해.
- 기존 웹사이트의 디자인과 기능을 임의로 변경하거나 삭제하지 마.
- 기존 로그인 및 회원가입 기능을 유지해.
- Supabase가 이미 연결되어 있다면 기존 연결 설정을 재사용해.
- 기존 코드와 컴포넌트는 최대한 재사용하고, 새로운 기능은 별도 컴포넌트로 분리해.
- 실제로 작동하는 기능을 구현하고, 클릭해도 아무 동작이 없는 버튼이나 가짜 매칭 결과는 만들지 마.
- 환경 변수와 API 키를 코드에 직접 작성하지 마.
- 구현이 끝나면 변경한 파일과 추가 설정이 필요한 사항을 설명해.

## 3. 사용자 취향 선택 페이지

페이지 제목:
'나와 취향이 맞는 로컬 메이트 찾기'

설명 문구:
'관심 있는 활동을 선택하면 당신의 여행 스타일에 어울리는 현지인 5명을 추천해 드려요.'

### 관심사 카테고리

사용자가 여러 항목을 선택할 수 있도록 체크박스 또는 선택형 태그 UI를 구현해.

1. 카페·음식
- 카페 탐방
- 로컬 맛집
- 베이커리
- 시장 및 길거리 음식
- 핫플레이스


2. 문화·취향
- 미술 및 전시
- 독서
- 빈티지숍
- 사진
- 음악 및 공연

3. 야외·일상
- 동네 산책
- 공원 및 자연
- 자전거
- 현지 시장 구경
- 숨겨진 장소 발견

4. 사람·교류
- 언어 교류
- 새로운 친구 만나기
- 현지 문화 이야기
- 보드게임
- 함께 요리하기

### 추가 매칭 조건

다음 항목도 선택할 수 있게 해.

- 여행 도시
- 여행 날짜 또는 만남 희망 날짜
- 여행 스타일: 여유로운 여행 / 활동적인 여행 / 현지인처럼 여행 / 새로운 경험
- 교류 방식: 깊은 대화 / 가벼운 친목 / 활동 중심
- 선호 언어: 한국어 / 영어 / 현지어 / 언어 무관

관심사를 하나 이상 선택해야 추천을 시작할 수 있도록 해. 필수 항목이 누락되면 사용자에게 안내 메시지를 보여줘.

## 4. 현지인 추천 알고리즘

사용자의 선택과 현지인의 프로필을 비교해 적합도가 높은 현지인 5명을 추천해.

초기 추천 점수는 다음 가중치를 사용해.

- 관심사 일치도: 40%
- 여행 스타일 일치도: 15%
- 교류 방식 일치도: 15%
- 사용 언어 일치도: 10%
- 일정 일치도: 20%

각 항목을 0~100점으로 환산한 뒤 가중합을 계산해 최종 매칭 점수를 구해.

매칭 점수 계산식:

최종 점수 = 관심사 일치도 × 0.40 + 여행 스타일 일치도 × 0.15 + 교류 방식 일치도 × 0.15 + 언어 일치도 × 0.10 + 일정 일치도 × 0.20

추천 조건:
- 선택한 여행 도시와 활동 지역이 일치해야 해.
- 현지인 프로필이 공개 상태여야 해.
- 현지인이 선택한 날짜에 실제로 만날 수 있어야 해.
- 차단된 사용자나 이용할 수 없는 계정은 제외해.
- 매칭 점수가 높은 순으로 추천하되, 가능한 경우 서로 다른 관심 분야의 현지인을 포함해 다양한 경험을 제안해.
- 조건에 맞는 현지인이 5명보다 적으면 실제로 존재하는 인원만 보여주고, 부족한 이유를 안내해. 가짜 프로필을 생성하지 마.

추천 카드에는 다음 내용을 표시해.
- 프로필 사진
- 이름 또는 닉네임
- 거주 도시
- 자기소개
- 주요 관심사
- 사용 가능 언어
- 추천 적합도 점수
- '당신과 잘 맞는 이유' 설명
- 후기 평점 및 후기 수
- 예약 가능한 일정
- 프로필 상세 보기 버튼
- 관심 목록 저장 버튼
- 매칭 요청 버튼

## 5. 현지인 프로필 상세 페이지

현지인 카드를 클릭하면 상세 페이지를 보여줘.

포함할 항목:
- 프로필 사진과 닉네임
- 자기소개
- 거주 도시 및 주로 활동하는 동네
- 취미와 관심사
- 사용 가능 언어와 숙련도
- 함께할 수 있는 활동
- 추천하는 로컬 장소
- 가능한 날짜와 시간
- 예상 소요 시간
- 비용이 발생하는 경우 비용과 포함 사항
- 후기 목록
- 인증 상태
- 매칭 요청 버튼

인스타그램 아이디는 기본적으로 공개하지 말고, 필요하다면 사용자가 공개 여부를 직접 선택하도록 해.

## 6. 1:1 매칭 요청 및 상태 관리

사용자가 현지인에게 매칭 요청 버튼을 누르면 요청 양식을 보여줘.

양식 항목:
- 여행 날짜
- 희망 시간
- 원하는 활동
- 만남 장소 또는 희망 지역
- 현지인에게 보내는 메시지

요청 제출 후에는 현지인에게 요청이 도착하도록 구현해.

매칭 요청 상태:
- pending: 응답 대기
- accepted: 수락
- declined: 거절
- cancelled: 취소
- completed: 만남 완료

현지인은 받은 요청을 확인하고 수락하거나 거절할 수 있어. 요청자는 본인의 요청 상태를 확인하고 대기 중인 요청을 취소할 수 있도록 해.

동일한 사용자와 현지인 사이에 동일 일정의 중복 요청이 생성되지 않도록 처리해.

## 7. 웹사이트 내 메시지 기능

매칭 요청을 주고받는 사용자가 사이트 내에서 소통할 수 있도록 메시지 기능을 구현해.

- 사용자 간 1:1 대화
- 메시지 작성 및 전송
- 메시지 전송 시간 표시
- 대화 목록과 최근 메시지 표시
- 읽지 않은 메시지 수 표시
- 차단 및 신고 기능

메시지는 실제 로그인한 사용자만 자신이 참여한 대화를 읽고 쓸 수 있도록 권한을 설정해.

실시간 기능이 이미 프로젝트에 구성되어 있지 않다면 Supabase Realtime을 적절히 설정하거나, 우선 메시지 조회 및 전송 기능부터 구현해. UI만 있고 실제 메시지가 저장되지 않는 형태로 끝내지 마.

## 8. 후기 기능

실제로 예약이 완료된 사용자만 해당 만남에 대한 후기를 작성할 수 있도록 해.

후기 항목:
- 전체 만족도 별점
- 의사소통
- 시간 준수
- 활동 만족도
- 구체적인 후기 내용
- 함께한 활동 유형
- 작성일

후기 작성 권한은 완료된 예약과 연결해 검증해. 한 예약에 대해 중복 후기가 작성되지 않도록 해.

현지인 프로필에는 후기 평균 점수와 후기 수를 표시해. 사용자가 부적절한 후기를 신고할 수 있도록 해.

## 9. Supabase 데이터베이스 설계

기존 데이터베이스 구조를 먼저 확인하고, 필요한 테이블만 추가해.

필요한 데이터 구조 예시:

- profiles: 사용자 기본 정보, 닉네임, 프로필 사진, 자기소개, 계정 유형, 공개 상태
- local_preferences: 현지인의 관심사, 활동, 언어, 여행 스타일
- traveler_preferences: 여행자의 관심사, 여행 스타일, 교류 방식, 선호 언어
- availability: 현지인의 날짜별 예약 가능 시간
- match_requests: 여행자, 현지인, 일정, 활동, 메시지, 요청 상태
- conversations: 대화 참여자 및 매칭 요청 연결 정보
- messages: 대화 ID, 발신자 ID, 메시지 내용, 전송 시간
- reviews: 예약 ID, 작성자 ID, 대상 사용자 ID, 별점, 세부 평가, 후기 내용
- favorites: 사용자가 저장한 현지인

테이블을 생성할 때 사용자 ID는 기존 Supabase Auth 사용자 ID와 연결해.

관심사와 언어를 여러 개 저장할 수 있도록 적절한 관계형 구조를 사용해. 기존 데이터와 충돌하는 중복 테이블을 무작정 생성하지 마.

## 10. 보안 및 권한



- 사용자는 자신의 프로필과 취향 정보를 수정할 수 있어.
- 공개된 현지인 프로필은 비로그인 사용자에게 공개할지 여부를 기존 서비스 정책에 맞게 결정해. 비공개 정보는 노출하지 마.
- 사용자는 자신이 보내거나 받은 매칭 요청만 조회할 수 있어.
- 대화 참여자만 해당 대화의 메시지를 조회하거나 작성할 수 있어.
- 사용자는 자신의 후기만 작성할 수 있어.
- 후기 작성 시 완료된 예약의 참여자 여부를 서버 측 권한 정책으로 검증해.
- 일반 사용자가 다른 사용자의 인증 정보, 비공개 연락처, 내부 운영 데이터를 조회할 수 없도록 해.
- 클라이언트에서 전달한 사용자 ID나 매칭 점수를 무조건 신뢰하지 마.

## 11. 디자인 가이드

기존 Roamly 웹사이트의 디자인을 유지해.

브랜드 방향:
- 따뜻하고 차분한 여행 감성
- 자연스러운 크림색, 세이지 그린, 올리브 그린 계열
- 과도한 그림자와 장식은 피하고 깔끔한 카드 디자인 사용
- 둥근 선택형 태그와 직관적인 아이콘 활용
- 현지인의 사진과 실제 활동이 잘 보이는 레이아웃
- 모바일에서도 사용하기 편한 반응형 UI

화면 구성:
1. 취향 선택 페이지
2. 추천 현지인 5명 페이지
3. 현지인 상세 프로필 페이지
4. 매칭 요청 양식
5. 받은 요청 및 보낸 요청 관리 페이지
6. 1:1 메시지 페이지
7. 후기 페이지
