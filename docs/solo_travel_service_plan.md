# Roamly 웹서비스 기획안

> **Roamly — Find your own way around.** (브랜드 방향: 정해진 코스가 아니라 내 방식대로 동네를 돌아다니는 여행)
>
> **브랜드 카피**: "혼자 떠나도, 혼자 헤매지 않도록"
> 어디를 가야 할지 막막한 순간부터 현지인과 함께하는 특별한 경험까지. 믿을 수 있는 로컬 정보로 혼자 떠나는 여행을 더 가볍고 풍성하게 만들어 보세요.

> 혼자 여행하는 사람이 **현지인의 시선으로 동네를 탐색하고, 일정을 짜고, 필요하면 현지인·동행과 연결되는** 웹서비스

---

## 1. 서비스 정의

| 항목 | 내용 |
|---|---|
| 타깃 | 전 세계 혼자 여행하는 20~40대(한국어·영어·일본어·중국어·스페인어·독일어 사용자). 유명 관광지보다 일상·동네·취향 중심 여행을 선호하고, 혼자 식사·방문이 부담스러운 순간이 있음 |
| 핵심 가치 | ① 현지인이 검증한 장소·팁 ② 혼자여도 부담 없는 연결 ③ 탐색→일정→기록이 한 곳에서 이어짐 |
| 차별점 | 관광지 랭킹이 아닌 **"동네 + 현지인 + 취향"** 기준 / 해외 식품 현지 리뷰 / 신뢰 표시 체계 |

## 1-1. 시장 근거 (혼행 수요 데이터)

> 작성 원칙: 출처가 확인된 수치만 본문에 싣고, 원문 대조가 끝나지 않은 수치는 "확인 필요"로 분리했다. 검색량·설문 의향은 실제 여행자 비율이 아니므로 "관심도 지표"로 표기한다.

### 확인된 수치
| 구분 | 수치 | 성격 | 출처 |
|---|---|---|---|
| 1인 여행 관심도 | 전년 대비 +9% (2026.1~5월) | 숙소 검색 데이터 | 아고다, [뉴시스 2026.7.20](https://www.newsis.com/view/ALSX20260720_0000006994) |
| 1인 숙소 검색량 | 국내 +7%, 해외 +11% | 숙소 검색 데이터 | 동일 |
| 지역별 급증 사례 | 동해 +28%, 자카르타 30배 이상 | 숙소 검색 데이터 | 동일 |
| 국내 혼행 인기 지역 | 서울, 제주, 부산, 인천, 강릉 | 숙소 검색 데이터 | 동일 |
| 해외 혼행 인기 지역 | 도쿄, 오사카, 후쿠오카, 자카르타, 다낭 | 숙소 검색 데이터 | 동일 |
| 혼행 수요 피크 시기 | 3월 > 1월 > 4월 > 2월 > 5월 | 숙소 검색 데이터 | 동일 |
| 올해 혼자 여행 계획 | 한국 응답자 약 4명 중 1명 | 설문 (표본 수·방법 미공개) | 아고다 2026 Travel Outlook, 동일 기사 |
| 국내여행 동반자 | 가족 59.9%, 친구/연인 35.7% (2023, 중복응답) | 공식 통계 | 한국관광공사 [관광지식정보시스템 국민여행조사](https://know.tour.go.kr/ptourknow/tourgoInfoView19Re.do?seq=103285) |

### 확인 필요 (원문 대조 전에는 본문 인용 금지)
| 항목 | 현재 상태 | 확인 방법 |
|---|---|---|
| 1인 해외여행 비중 2018년 3.7% → 2019년 4.2% → 2023년 4.6% | 출처가 문화체육관광부 국민여행조사로 보도되었으나, 검색 결과마다 출처 표기가 다르고 원문 미확인 | 2023 국민여행조사 보고서(통계편) 해외여행 동반자 항목 |
| 혼자 여행 비율 (2018 2.5% → 2019 4.1% → 2020 4.8%) | 2차 인용 기사만 확인, 2020년까지 | 해당 연도 국민여행조사 보고서 |
| 2024~2025 혼자 여행 비율 | 공식 수치 미확보. 2023 국내여행 동반자 상위 5개 항목에 "혼자"가 없어 역산 불가 | 2024년 국민여행조사 통계편, 또는 한국문화관광연구원 공개 원자료로 직접 집계 ([data.go.kr](https://www.data.go.kr/data/15052709/fileData.do)) |
| 에어프레미아 노선별 1인 발권 비중 (뉴욕 53.2%, 방콕 28.8%) | 항공사 자체 탑승 데이터. 단독 발권 기준이라 동행 별도 예약 포함 가능 | 에어프레미아 보도자료 원문. 인용 시 "일부 항공사 데이터"로 표기 |

### 해외 참고 (민간 조사, 인용 시 출처 명시)
- Hostelworld 2025 조사: "새로운 사람을 만나고 싶다" 응답 58% (2024년 43%) → 연결 기능의 근거
- 글로벌 시장 규모 추정치(2024년 약 4,823억 달러, 2030년 약 1조 700억 달러)는 시장조사 업체 간 편차가 커서 **기획안 인용은 권장하지 않음**

### 기획안에 주는 시사점
1. 한국 혼행 수요는 **국내·해외 모두 증가세**이며 해외 증가폭이 더 크다 → 도시 선택 시 도쿄·오사카·후쿠오카가 유력
2. 공식 통계상 혼행의 **절대 비중은 아직 낮다** → "전체 시장 규모"가 아니라 **성장하는 니치 + 높은 페인포인트(혼밥, 안전, 외로움)** 로 포지셔닝
3. 수요 피크가 3월·1월 → 출시/마케팅 타이밍 근거

## 1-2. 확정 방향: 글로벌·다국어·도시 선택형

| 항목 | 결정 |
|---|---|
| 타깃 | 각국의 혼행객 (글로벌) |
| 지원 언어 | 한국어, 영어, 일본어, 중국어, 스페인어, 독일어 |
| 도시 선택 | 이용자가 도시를 선택. 미오픈 도시는 **"도시 요청" → 요청이 기준 수 이상 모이면 오픈** |
| 론칭 도시 | **서울, 도쿄, 오사카, 베를린, 뉴욕, 바르셀로나** (선정 근거는 아래) |
| 2차 후보 | 후쿠오카, 방콕, 다낭 (아시아 혼행 수요) |

### 론칭 도시 선정 근거
| 도시 | 근거 |
|---|---|
| 서울 | 시드 콘텐츠 확보가 가장 쉬운 홈 도시. 방한 외국인(2024년 약 1,637만 명) 대상 현지인 연결 수요. 한국 혼행 인기 국내 1위 (아고다 2026) |
| 도쿄 | 한국 혼행객 해외 1위 (아고다 2026). 일본 국민의 혼자 휴가 비율이 5년간 약 2배로 증가해 **일본 사용자(공급·수요)** 확보에 유리 |
| 오사카 | 한국 혼행객 해외 2위 (아고다 2026). 도쿄와 묶어 "일본 2도시"로 운영하면 현지인 호스트 모집과 콘텐츠 운영을 같은 팀·언어로 처리 가능 |
| 베를린 | 독일어 사용자 확보용. 독립 서점·마켓·로컬 문화 등 서비스 콘셉트(동네·취향 탐색)와 맞는 도시 |
| 뉴욕 | 영어 사용자 확보용. 항공사 데이터에서 1인 발권 비중이 가장 높았던 노선(에어프레미아, 원문 확인 필요) |
| 바르셀로나 | 스페인어 사용자 확보용. 동네 단위 탐색·마켓 문화가 강해 동네 중심 콘셉트와 맞음 |

> 베를린·바르셀로나는 데이터 근거가 아니라 **언어 커버리지와 콘셉트 적합성** 기준으로 선정했다. 혼행 수요 데이터는 별도 확인이 필요하다.

### 도시 운영 리스크
- 6개 도시는 도시당 시드 콘텐츠(20~30곳)와 현지 에디터·호스트 확보가 필요하다. 팀 규모가 작다면 **서울·도쿄·오사카를 먼저 열고, 베를린·뉴욕·바르셀로나는 "오픈 예정(도시 요청 접수)" 상태로 시작**하는 단계적 오픈을 고려한다.

### 언어 운영 원칙
- **UI는 6개 언어**를 지원하되, **콘텐츠는 원어로 작성 + 자동 번역**(번역본 표시, 원문 보기 제공)으로 시작한다. 6개 언어로 직접 콘텐츠를 만드는 것은 초기에 불가능하다.
- 론칭 도시 3곳의 호스트 작성 언어는 한국어·일본어 중심이므로, **스페인어·독일어 사용자는 번역 콘텐츠의 소비자**로 시작한다.
- 후기·신뢰 배지 문구는 번역 시 의미가 달라지지 않도록 고정 문구로 관리한다.

## 1-3. 수익 모델과 현지인 보상

| 역할 | 보상 방식 | 비고 |
|---|---|---|
| 콘텐츠 작성(장소·팁·리뷰) | 배지·등급, 노출 우대, 크레딧 | **금전 보상 없음** (광고성 후기 방지) |
| 프로그램 진행(산책·탐방) | 호스트가 가격 설정, 플랫폼이 건당 **비율 수수료(10~20%)** 징수 | 건당 고정 지급은 플랫폼 부담이 커서 비권장 |
| 초기 호스트 확보 | 첫 N건 수수료 면제, 초기 노출 우대 | 기간 한정 |
| 여행자 동행 | **무료 매칭**, 수수료 없음 | 유료화 시 이용 저하 우려 |
| 감사 표시 | 여행자가 호스트에게 팁(후원) | 후순위 |
| 식품 | 구매 링크 제휴 수익 일부 공유 | 제휴 표기 필수 |

### 선행 확인 사항 (출시 전)
- **국가별 규제**: 현지인이 유상으로 외국인을 안내하는 행위에 자격·영업 규제가 있는 나라가 있다(예: 한국의 관광안내 관련 법규). 법률 전문가 확인 전에는 **"무료 동네 산책 + 실비 분담"** 형태로 시작한다.
- **세금·정산**: 국가별 결제·정산 사업자 선정 필요
- **안전**: 호스트 신원 확인, 공공장소 만남, 신고 기능이 수익 모델보다 먼저 정해져야 한다

## 2. 기능 중복 정리 (22개 → 6개 모듈)

| 통합 모듈 | 흡수한 기능 | 정리 이유 |
|---|---|---|
| **M1. 동네·장소 탐색** | 현지인 추천 장소, 동네 탐색, 취향에 맞는 동네 찾기, 현지 생활 꿀팁 | 모두 "장소/동네 상세 페이지"를 보는 같은 흐름. 꿀팁(운영 요일·결제·방문 시간)은 별도 기능이 아니라 **장소 카드의 필드**. 취향 동네는 동네 목록의 **필터/추천 정렬** |
| **M2. 내 여행 (일정·예산·준비)** | 일정 만들기, 예산 관리, 준비물 관리, 장소·제품 저장, 여행 기록 | 저장함 = 일정 후보함, 여행 기록 = 지난 일정에 사진·메모를 붙인 것. 모두 **Trip(여행) 하나를 중심으로 한 탭**으로 구성 |
| **M3. 지금 뭐 하지 (즉흥 추천)** | 즉흥 일정 추천 | 단독 기능이 아니라 M1 데이터 + 남은 시간·날씨·기분 조건의 **추천 레이어**. 일정 화면의 빈 시간대에 노출 |
| **M4. 로컬 프로그램 & 동행** | 현지인 프로필 선택, 현지인과 동네 산책, 현지인과 맛집·마켓 탐방, 예약·일정 조율, 여행자끼리 동행 | 산책/맛집·마켓 탐방은 **같은 "프로그램" 객체의 유형 태그**. 프로필 선택 + 예약은 하나의 호스트→프로그램→신청 흐름. 동행은 호스트가 여행자인 프로그램 유형 |
| **M5. 해외 식품 리뷰** | 현지인 음식 리뷰, 제품 비교·추천, 취향 기반 추천, 현지인에게 질문, 사진으로 식품 확인 | 제품 상세(리뷰·Q&A·비교)가 중심. 취향 기반 추천은 **리뷰 정렬 옵션** |
| **M6. 커뮤니티 & 신뢰** | 정보 직접 공유, 후기·신뢰 관리 | 장소 추천·생활 팁·식품 리뷰·질문이 모두 **하나의 콘텐츠 작성 엔진**을 공유. 신뢰 표시(방문일·작성일·실경험)는 모든 콘텐츠에 붙는 **공통 레이어** |

**공통 기반(별도 기능이 아닌 인프라):** 계정/프로필(여행자·현지인), 취향 프로필(분위기·맛 취향·언어), 장소/제품 DB, 콘텐츠 신뢰 배지, 다국어.

## 3. 핵심 기능 정의

### M1. 동네·장소 탐색
- 도시 → **동네 카드**(분위기 한 줄, 대표 태그: 카페·디자인숍·자연·조용한 골목) → 장소 목록
- 장소 카드: 현지인 추천 코멘트, 카테고리(맛집·카페·공원·마켓·독립서점), **생활 팁**(운영 요일, 추천 메뉴, 결제 방법, 붐비는/좋은 시간대), 혼자 가기 좋음 여부
- 취향 온보딩(3~5문항) 결과로 동네 추천 정렬
- 모든 장소에 "저장" / "일정에 추가"

### M2. 내 여행
- 여행 생성(도시·기간) → **일정**(날짜별 장소 추가, 드래그 순서, 지도 동선·이동시간)
- **예산**: 카테고리(교통·숙박·식비·기타) 목표 vs 지출 기록
- **준비물/할 일**: 템플릿 체크리스트
- **저장함**: 장소·제품 후보 → 일정에 끌어넣기
- **기록**: 여행 후 방문 장소에 사진·메모 → 도시별 아카이브 (일정이 그대로 기록으로 전환)

### M3. 즉흥 추천
- 입력: 남은 시간 · 현재 날씨(자동) · 기분(조용히/활동적/배고픔 등) · 현재 위치
- 출력: 지금 갈 만한 장소/프로그램 3~5개 + "일정에 추가"

### M4. 로컬 프로그램 & 동행
- **호스트 프로필**: 소개, 언어, 관심사, 소개 지역·활동, 후기
- **프로그램**: 유형(동네 산책 / 맛집·마켓 탐방 / 동행 식사·방문), 일시, 소요시간, 비용, 정원(소규모), 만나는 곳
- **신청 흐름**: 프로그램 탐색 → 신청(메시지) → 호스트 수락 → 일정 확정 → 내 일정에 자동 반영
- 동행: "이 날 이 식당에 같이 갈 여행자" 모집 글 형태

### M5. 해외 식품 리뷰
- 제품 상세: 현지인 리뷰(맛·식감·재구매 의향 구조화), 성분·먹는 방법, 가격대
- 비교: 가격 · 맛 · 인기 · 선물 적합도 기준 나란히 보기
- 취향 기반 정렬: 단/짠/매운 취향이 비슷한 사용자 리뷰 우선
- 질문하기: 제품에 질문 → 현지 사용자 답변
- 사진 검색(후속): 제품 사진 → 제품 매칭

### M6. 커뮤니티 & 신뢰
- 작성 유형: 장소 추천 / 생활 팁 / 식품 리뷰 / 질문
- **신뢰 배지**: 방문일, 작성일, 실경험 인증(영수증·위치·사진 메타), 현지인/여행자 구분, 광고·협찬 표기
- 광고성 의심 신고, 운영자 검수 큐, 오래된 정보 "정보 갱신 필요" 표시

## 4. 사용자 흐름

### 흐름 A. 여행 전 (기획)
`가입 + 취향 온보딩` → `도시 선택` → `취향 맞춤 동네 추천` → `동네/장소 탐색 (현지인 코멘트·생활 팁)` → `저장` → `새 여행 만들기` → `저장함에서 일정으로 배치 + 동선 확인` → `예산 목표·준비물 체크리스트 설정`

### 흐름 B. 여행 중 (실행)
`오늘 일정 확인` → 빈 시간 발생 → `즉흥 추천 (시간·날씨·기분)` → `일정 추가` / 혼자 먹기 부담 → `동행·로컬 프로그램 탐색 → 신청` → `현장에서 지출 기록` → `방문 체크 + 사진·메모`

### 흐름 C. 여행 후 (기록·기여)
`여행 기록 정리 (도시별 아카이브)` → `방문한 장소에 추천/팁 작성 (실경험 배지 자동 부여)` → `후기 공유`

### 흐름 D. 식품 쇼핑 (독립 진입)
`제품 검색 / 사진` → `제품 상세 (현지인 리뷰·성분)` → `비교 / 질문하기` → `저장함 → 구매 리스트로 일정·준비물에 연결`

### 흐름 E. 현지인 (공급자)
`호스트 가입 (소개·언어·지역)` → `추천 장소·팁 작성` → `프로그램 등록` → `신청 수락·일정 조율` → `후기 수신`

## 5. MVP 개발 우선순위

**원칙:** 콘텐츠가 없으면 서비스가 비어 보이고(콜드 스타트), 결제·안전이 얽힌 기능은 운영 부담이 크다. 따라서 **"볼 것이 있고 → 내 것으로 담고 → 일정이 된다"를 먼저** 검증하고, 사람 간 연결은 그다음 단계로 둔다.

### P0 — MVP (서울·도쿄·오사카·베를린·뉴욕·바르셀로나 6개 도시 한정)
| 기능 | 범위 |
|---|---|
| 다국어 UI + 콘텐츠 자동 번역 | UI 6개 언어, 콘텐츠 원어 작성 + 번역본·원문 전환 |
| 도시 선택·도시 요청 | 론칭 도시 선택, 미오픈 도시 요청 접수 |
| 계정 + 취향 온보딩 | 이메일/소셜 로그인, 취향 3~5문항 |
| 동네·장소 탐색 | 동네 카드, 장소 카드(현지인 코멘트 + 생활 팁 필드), 카테고리·태그 필터 |
| 장소 저장 | 개인 저장함 |
| 일정 만들기 | 날짜별 배치, 순서 변경, 지도 보기 |
| 콘텐츠 작성(최소) | 장소 추천/팁 작성 + **방문일·작성일·실경험 표시** (신뢰 레이어 기초) |
| 시드 콘텐츠 | 운영팀·초기 현지인 에디터가 직접 작성 (동네당 20~30곳 목표) |

### P1 — 리텐션
- 예산 관리, 준비물 체크리스트
- 즉흥 일정 추천(규칙 기반: 시간·날씨·카테고리)
- 여행 기록(사진·메모, 일정 → 기록 전환)
- 호스트 프로필 + 현지인 콘텐츠 작성 확대
- 신고/검수 기능(광고성 리뷰 관리)

### P2 — 연결 & 식품
- 로컬 프로그램(동네 산책, 맛집·마켓 탐방) 등록·신청·일정 조율 (**결제는 처음엔 오프라인/수동 정산**, 호스트 검증 절차 선행)
- 해외 식품: 제품 DB + 구조화 리뷰 + 질문하기
- 취향 기반 리뷰 정렬, 제품 비교

### P3 — 확장
- 여행자 동행 매칭(안전·신고 체계 선행 필요)
- 사진으로 식품 확인(이미지 인식/제품 DB 필요)
- 개인화 추천 고도화, 온라인 결제·정산, 앱/PWA

### 우선순위 근거
| 후순위로 미룬 것 | 이유 |
|---|---|
| 동행·프로그램 | 사람 간 만남은 **안전·신뢰·결제·분쟁** 이슈 동반. 콘텐츠와 사용자 기반이 생긴 뒤 |
| 사진 식품 검색 | 제품 DB와 이미지 인식 비용이 큼. 텍스트 검색으로 먼저 검증 |
| 식품 리뷰 | 장소 서비스와 사용자 맥락이 달라 별도 시드 필요. 장소 MVP 검증 후 확장 |
| 개인화 추천 | 데이터가 쌓이기 전엔 태그 기반 규칙으로 충분 |

## 8. 구현 현황 (프로토타입, 2026-10-15 기준)

> 한 줄 요약: **P0·P1·P2의 화면과 규칙을 동작하는 프로토타입으로 구현**했다(2026-10-15 갱신: MY, 호스트·로컬 프로그램·동행, 해외 식품 리뷰, 일정 지도 추가). 단, 로그인·서버가 없어서 **모든 데이터는 한 브라우저에만 저장**되고, 콘텐츠는 가상의 예시다(장소 12곳, 프로그램 7개, 식품 8개). 따라서 "사용자 간 공유"가 필요한 부분(후기 공유, 신고 집계, 호스트 수락)은 시연용 값·시연 버튼으로만 확인했다.

## 10. 결정이 필요한 것
1. **백엔드 방식**: BaaS(예: Supabase 계열)로 빠르게 시작할지, 직접 서버를 만들지. 비용·개인정보(EU 이용자)·장기 운영을 비교해 결정
2. **시작 도시의 콘텐츠 범위**: 서울·도쿄·오사카 3곳을 먼저 채우고 나머지 3곳은 "오픈 예정"으로 둘지
3. **현지인 인증 강도**: 신분증 기반 vs 자기신고 + 샘플 검수
4. **증빙·사진 보관 기간과 위치 처리 방침**(개인정보 검토 후)
5. **번역 방식**: 기계번역 + 신고 기반 교정으로 시작할지
6. **장소 데이터 출처**: 외부 지도·장소 DB를 쓸지, 자체 구축할지
7. **시장 근거 자료**: 공식 통계(국민여행조사 2024~2025) 확보 방법

3. 호스트·로컬 프로그램(P2) 설계는 법률 확인과 함께 시작
